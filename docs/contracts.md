# Shared contracts (v1 — proposed by thread 1, engine)

Owned by the coordination thread. Changing anything here = PR + board post tagging @all.

v1 is backward compatible with v0 and with the API mock (`api/mock_engine.py`): same envelope (`current`, `path`, `nodes[].status`, `result`), same field names where v0 had them; v1 only adds fields. The engine (`core/`) produces every shape below; real, full examples generated by the code are in `core/examples/*.json` (`python -m core.examples.generate`).

## Conventions

- Money in CHF, numbers rounded to 2 decimals. Rates as decimals (0.05 = 5%). JSON keys snake_case.
- Months are 0-based from the profile's `as_of` (month 0 = the month of `as_of`). Windows are half-open `[from_month, to_month)`; `to_month: null` = until the end.
- **Stock series** (`cash`, `investments`, `debt`, `net_worth`, bands) have `horizon_months + 1` points: index 0 = opening balance, index k = balance at the END of month k-1. **Flow series** (`flows.*`) have `horizon_months` points: index t = month t.
- Month indices in metrics are 0-based: `first_negative_month: 6` means "month 7" in the UI.
- Incomes are **net of social contributions, before income tax** (Swiss reality: income tax is billed separately). The engine deducts a simplified income tax (assumption `AS-income-tax`).
- Planned amounts are in today's prices; the engine applies inflation (expenses, one-offs, contributions) and wage growth (income). Loan payments are fixed in nominal CHF.

## Profile (roots)

Produced by the questionnaire or multimodal extraction. Unknown fields are ignored; missing optional fields default to 0 / empty.

```json
{
  "profile_id": "P00001",
  "display_name": "Alexia",
  "age": 20,
  "city": "Lausanne",
  "currency": "CHF",
  "as_of": "2025-01-01",
  "horizon_months": 120,
  "employment_status": "student",
  "cash": 8000,
  "monthly_net_income": 1200,
  "monthly_rent": 900,
  "monthly_other_expenses": 600,
  "monthly_investment_contribution": 0,
  "assets": [{"type": "investment", "value": 0, "label": "ETF"}],
  "liabilities": [{"type": "student_loan", "label": "Study loan", "principal": 0, "annual_rate": 0.0, "monthly_payment": 0}],
  "goals": [{"name": "Emergency savings", "target": 12800, "target_date": "2029-12-31", "priority": "high", "metric": "liquid"}],
  "provenance": {"monthly_net_income": {"source": "payslip_ocr", "confidence": 0.97}}
}
```

| Field | Notes |
|---|---|
| `horizon_months` | new, default 120 |
| `monthly_investment_contribution` | new, CHF/month moved from cash to investments when cash allows (a transfer, not an expense) |
| `assets[].type` | `investment` / `investment_portfolio` / `pension_3a` are simulated as one balanced portfolio; other types are ignored in v1 |
| `liabilities[]` | fixed payment, monthly rate = `annual_rate / 12`; optional `payment_start_month` (interest is capitalised before it) |
| `goals[].metric` | new, `liquid` (cash + investments, default) or `net_worth` (minus debt); tested at the end of the month of `target_date` |
| `provenance` | where each field came from (questionnaire, voice, document + extractor, user edit); the engine ignores it |

## Decision tree (data file, `core/data/trees/<name>.json`)

The tree content is editable data (decisions are OPEN in `docs/plan.md`). A node's interventions apply on top of all its ancestors' interventions, in order.

```json
{
  "tree_id": "alexia-v1",
  "assumptions": [{"id": "AS-alexia-master-tuition", "param": "master_tuition", "value": 2500, "unit": "CHF/year", "range": [1460, 8000], "...": "..."}],
  "root": {"node_id": "0", "label": "Today: student in Lausanne", "interventions": [], "children": [
    {"node_id": "2", "label": "Do a master's", "description": "...", "interventions": ["..."], "children": ["..."]}
  ]}
}
```

### Intervention

`value` is a number or a reference to an editable assumption: `{"assumption": "AS-...", "scale": 1}`.

| `param` | Fields | Effect |
|---|---|---|
| `monthly_net_income`, `monthly_rent`, `monthly_other_expenses`, `monthly_investment_contribution` | `op` (`set` / `add` / `mul`), `value`, `from_month`, `to_month` | changes the planned monthly amount in the window (never below 0) |
| `one_off_cost`, `one_off_income` | `month`, `value` (>= 0), `label` | one payment in that month |
| `new_liability` | `month`, `liability` {`type`, `label`, `principal`, `annual_rate`, `monthly_payment`, `payment_start_month`?} | loan received in cash in `month`; payments start at `payment_start_month` (default `month + 1`) |

```json
{"param": "monthly_net_income", "op": "set", "value": {"assumption": "AS-alexia-student-job"}, "from_month": 0, "to_month": 24, "label": "Student job"}
```

## Assumption

```json
{"id": "AS-inflation-mean", "param": "inflation_mean", "label": "Average annual inflation (CPI)", "value": 0.01, "unit": "1/year",
 "range": [0.0, 0.03], "kind": "assumption", "editable": true, "verified": false, "retrieved": "2026-11-21",
 "source": "FSO Swiss Consumer Price Index (https://www.bfs.admin.ch/...) and SNB price-stability definition 0-2% (https://www.snb.ch)"}
```

- `kind`: `observation` (published figure) or `assumption` (modelling choice informed by the source).
- `range` (optional): low/high used by the sensitivity tornado.
- `verified`: `false` = from team knowledge, to be checked against the source before the demo.
- After an override the item also carries `"user_edited": true` and `"default_value"`.
- Overrides are sent as `[{"id": "AS-...", "value": 4500}]` (API form) or `{"AS-...": 4500}`; `param` names also work as keys.
- Defaults: `core/data/assumptions_ch.json` (inflation, wage growth, returns, volatility, cash interest, job loss, unemployment insurance, unexpected expenses, income tax table, liquidity target, debt-service limit) + the tree's own assumptions.

## Weather (things the user does not choose)

Sent as `["recession", "inflation"]` or with parameters `[{"type": "recession", "start_month": 6, "duration_months": 12}]`. Applied to every visible node (comparisons stay like-for-like), to the deterministic path and to every Monte Carlo path.

| `type` | Defaults | Effect |
|---|---|---|
| `recession` | `start_month` 12, `duration_months` 18, `job_loss_multiplier` 3, `return_shift` -0.15 | job loss x3, no real wage growth, returns -15 pts/year in the window |
| `inflation` | `start_month` 0, `duration_months` 24, `annual_rate` 0.05 | prices rise at 5% while wages keep their usual pace |
| `market_crash` | `start_month` 12, `drop` 0.30 | investments lose 30% in one month |
| `job_loss` | `start_month` 12, `duration_months` 6 | income replaced by unemployment insurance (`AS-unemployment-replacement`) |

## `expand` result (POST `/tree/expand`)

Input: `{profile?, path, assumptions?, weather?, uncertainty?}`. `uncertainty` (default `false`) adds the optional Monte Carlo lens to every visible node; without it every result is deterministic (`n_paths: 0`). `path` = chosen node ids from the root: `[]`, `["2"]`, `["2", "2.2"]`. Back one level = `back_path`.

Visible nodes = root + chosen path (`status: "chosen"`) + siblings of the current node (`"sibling"`, show greyed) + children of the current node (`"child"`). Everything else is pruned and never simulated.

Ghost nodes (v1.1, additive): `pruned_nodes` = the siblings of every **ancestor** of the current node, i.e. the branches turned away from earlier. Draw them in grey with their label only, not clickable. They have **no `result`** (never simulated, cost ~0) and live in their own list, never in `nodes`, so clients that expect every entry of `nodes` to carry a `result` keep working. Example for `path: ["2", "2.1", "2.1.3"]`: `nodes` = 0, 2, 2.1, 2.1.3 (chosen) + 2.1.1, 2.1.2 (sibling) + children of 2.1.3; `pruned_nodes` = 1, 3 (siblings of 2) + 2.2, 2.3 (siblings of 2.1). At depth 1 the list is empty (the root has no siblings). Shape, for `path: ["1", "1.2"]` on the Alexia tree:

```json
"pruned_nodes": [
  {"node_id": "2", "parent_id": "0", "label": "Do a master's", "status": "pruned", "depth": 1, "has_children": true},
  {"node_id": "3", "parent_id": "0", "label": "Move abroad", "status": "pruned", "depth": 1, "has_children": true}
]
```

Meaning of the main fields:

- `deterministic`: central assumptions, no random shocks (no job loss, no unexpected expenses). This is the primary result: an "if these inputs hold, then..." path, not a forecast. Named weather scenarios move it deterministically.
- `uncertainty` / `mode` / `n_paths`: with `uncertainty: false` (default) no Monte Carlo runs: `n_paths: 0`; every `p10/p50/p90`, `shortfall_probability`, `min_cash_p10`, `avg_unemployed_months` and goal `probability`/`p50_value` are `null`; `goal_probability` is `{}`; `bands` keep their keys with empty arrays; the `bands_ordered` check has `applicable: false`; health `resilience`/`goals` use the deterministic path. Read `deterministic`, `metrics.final_*`, `goals[].met_deterministic` and `exploration`; never index bands without checking their length. `mode` stays `"deterministic"`: turning the lens on never changes the primary path.
- `bands` (lens on only): percentiles over `n_paths` Monte Carlo paths (random inflation per year, monthly market returns, job losses, unexpected expenses). "p10" = 10% of simulated paths end below this line. These are conditional on the assumptions, not real-world probabilities.
- `shortfall_probability` (lens on only): share of paths where cash goes below 0 at least once. Negative cash is an unfunded financing need, not an assumed loan (UBS starter-kit convention); investments are sold first if `AS-auto-liquidate` = 1.
- `liquidity_months`: (cash + investments) / monthly living expenses at the tightest month (negative = short by that many months).
- `sensitivity` (tornado): each assumption with a `range` moved to low and high, all else fixed; outcome = deterministic final net worth and whether cash goes negative (`cash_shortfall_low/high`), all variants in one batched pass. `shortfall_probability_low/high` stay `null` (kept for compatibility). Sorted by swing; assumptions with no effect on this node are omitted.
- `exploration` (default on for `simulate` and the current node of `expand`; `exploration=False` skips it): deterministic "what would have to be true" analyses, each re-running the same accounting engine with every other input fixed:
  - `levers`: the five assumptions that move this node most (from the tornado). Any assumption can be overridden per request with `assumptions: {id: value}`; `how_to_change` is a ready-made example.
  - `break_even`: one row per sibling (for a custom `/simulate` node with a `parent_id`: its parent). `delta_final_net_worth` = this node minus the peer at the horizon; `first_month_ahead` / `sustained_crossover_month` = first month index where this node is ahead (and stays ahead to the horizon); `salary_threshold` = the value of this node's latest income assumption at which both end level (`null` when that assumption has no `range`).
  - `goal_seek`: per dated goal, the extra monthly net income from month 0 to the goal month that meets it exactly.
  - `reverse_stress`: the smallest extra one-off cost in month 0 that pushes cash below -0.01 CHF or misses a dated goal; `result` / `missed_goals` describe the plan at that cost.
  - `timing`: this node's own decision delayed 12 and 24 months (ancestors keep their dates; the horizon end stays fixed). `window_shortened` = a monthly change is cut by the horizon; `omitted_interventions` = changes pushed past the horizon.
  - Threshold statuses: `threshold_found` (`value` within `tolerance` 0.01), `already_satisfied` (holds at the lower bound: `value` = that bound, or `null` for `salary_threshold`), `not_reached_within_bounds`, `lever_has_no_effect`, `non_monotone` (the search assumes an increasing margin checked on a 9-point grid and returns no value rather than a wrong one), `already_broken` (reverse stress with no extra cost). `margin_at_bounds` = margin at both bounds in CHF (reverse stress: positive = broken). Income/cost searches stop at CHF 1,000,000, an explicit search bound, not a plausible value.
- `checks`: accounting identities verified on every run; the UI can show them as a "verified" badge.
- `trace_id`: hash of all inputs (profile, interventions, assumptions, weather, seed); same inputs = same result.

## API (thread 2) — routes

| Method | Route | Purpose |
|---|---|---|
| POST | `/profiles/extract` | multipart files/audio/text → Profile + provenance + cost/latency |
| POST | `/tree/expand` | `{profile, path, assumptions, weather}` → `expand` result |
| POST | `/simulate` | `{profile, node, assumptions, weather}` → SimulationResult |
| POST | `/agent/ask` | `{question, context}` → answer + tool traces (numbers only from engine) |
| POST | `/voice/stt`, `/voice/tts` | speech in/out |
